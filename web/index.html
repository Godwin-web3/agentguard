How it works

The agent proposes. The mandate decides.

Agents never hold PayPal credentials. Every payment goes through three steps, and money only moves after the last one.

01 · reserve

Reserve against a signed mandate

A deterministic policy engine checks payee, SKU, category, quantity, per-transaction and total limits against a mandate the user signed with their passkey. Budget is reserved atomically, so parallel agents cannot double-spend it.

propose_payment → reserved | needs_human | rejected

02 · verify

Verify with PayPal, and with the user

AgentGuard authorizes on the user's vaulted wallet, then reads PayPal's own view of amount, currency and payee. Anything above the user's threshold waits for a passkey approval bound to that exact order.

intent: AUTHORIZE · payee + amount re-checked

03 · capture

Capture, or void, and prove it

Captures run only while the mandate is still active, checked again under lock. Mismatches and revocations void instead. Each capture yields a Proof-of-Intent receipt with a hash-chained audit entry.

captured → receipt + RFC 3161 + anchor

Proof-of-Intent receipt

Evidence that holds up without trusting us.

The receipt bundles the user's passkey signature, the order PayPal reported, the approval and the capture. The issuer signs it, two independent timestamp authorities stamp it, and the audit log is anchored.

  • Verifies offline with the open-source intent-verifier, or in your browser.
  • Retired issuer keys stay published, so old receipts keep verifying after rotation.
  • Submitted as seller evidence on a live PayPal sandbox dispute, which PayPal accepted for review. No outcome is claimed.

Security model

What we guarantee, and where it stops.

The server holds no key that can authorize spending. AI risk analysis is advisory: it can escalate a payment to a human, never approve a failing one.

Enforced

  • Mandates, revocations and approvals are signed by the user's passkey. The server re-verifies them on every proposal, approval and capture.
  • Approvals are single-use and bound to the exact proposal hash, PayPal order, amount and a five-minute nonce.
  • Payee allowlists are checked against the payee PayPal reports, not only what the agent claims.
  • Idempotency keys and PayPal-Request-Id on every money call. Recovery never captures against an inactive mandate.
  • Every decision lands in a hash-chained, append-only audit log, anchored with RFC 3161 timestamps.

Honest limits

  • The first passkey enrollment is bootstrapped by whoever holds the admin token. Deliver links over your own authenticated channel.
  • Admin recovery is time-locked for 72 hours and announced, so a takeover is visible as RECOVERY in receipts, not prevented.
  • An anchor proves history as of its time. Detecting a forked history needs someone outside to keep copies of the anchors.
  • A leaked issuer key stays valid for what it signed before retirement. Rotate promptly, together with the admin token.
  • AP2 objects are plain JSON claim sets, not SD-JWT, and the cart JWT is unsigned. Merchant authenticity comes from PayPal's API.
Quickstart

Running locally in about five minutes.

Node 22, a PayPal sandbox app and nothing else. SQLite locally; Postgres and Vercel for deployment.

Full guide MCP server
shell
# sandbox credentials only
git clone https://github.com/Godwin-web3/agentguard && cd agentguard
npm ci && npm run build:web
export PAYPAL_CLIENT_ID=… PAYPAL_CLIENT_SECRET=…
export AGENTGUARD_ADMIN_TOKEN=$(openssl rand -hex 24)
npm start   # http://localhost:8787/console
agent → AgentGuard
curl -X POST localhost:8787/v1/agent/payments \
  -H "authorization: Bearer $AGENT_KEY" \
  -H "content-type: application/json" \
  -d '{"agent_id":"agt_…","mandate_id":"mdt_…",
       "paypal_order_id":"8FF9…","idempotency_key":"order-8110"}'
# → { "decision": "needs_human", "approval_id": "apr_…" }
anyone, offline
curl https://agentguard-orcin.vercel.app/.well-known/agentguard-keys \
  > keys.json   # pin this
npx intent-verify receipt.json --issuer-keys keys.json
# VALID · passkey ✓ · issuer ✓ · 2 × RFC 3161 ✓ · anchor ✓
